# Documentação — RF01 a RF06

## 1. Visão geral

Nesta etapa do projeto foi desenvolvida a parte responsável pela **inicialização, leitura, validação, tratamento, resumo e persistência dos dados**.

O escopo desenvolvido corresponde aos requisitos **RF01 a RF06**. Os requisitos posteriores serão desenvolvidos por outros integrantes da equipe.

A aplicação foi preparada para execução utilizando **Docker Compose**, com o PostgreSQL como banco de dados principal desta etapa.

---

## 2. O que foi desenvolvido

### RF01 — Inicialização e configuração

Foi implementada a inicialização da aplicação por meio do módulo principal:

```bash
python -m src.main
```

As configurações e informações de conexão são mantidas fora da lógica principal da aplicação, utilizando arquivos de configuração e variáveis de ambiente.

Também foram adicionados registros de log indicando o início e o término do processamento.

---

### RF02 — Leitura das fontes

A aplicação realiza a leitura de três fontes principais:

* `dados/brutos/catalogo.csv`
* `dados/brutos/interacoes.json`
* `dados/brutos/comentarios.json`

Na execução realizada, foram lidos:

* 1000 registros do catálogo;
* 1000 registros de interações;
* 1000 registros de comentários.

Total:

**3000 registros lidos.**

A aplicação registra no log o arquivo utilizado e a quantidade de registros encontrados.

---

### RF03 — Validação

Após a leitura, os dados passam por uma etapa de validação.

São verificadas informações como campos obrigatórios, valores, identificadores, categorias, datas e possíveis duplicidades.

Na execução atual:

* 3000 registros válidos;
* 0 inválidos;
* 0 incompletos;
* 0 duplicados.

Também foram contabilizadas 1000 correções no catálogo durante o processamento.

---

### RF04 — Tratamento e padronização

Os dados são tratados antes de serem armazenados.

Entre os tratamentos realizados estão:

* remoção de espaços extras;
* padronização dos dados;
* conversão de valores;
* tratamento de campos;
* identificação de duplicidades;
* organização dos dados processados.

Os dados tratados são armazenados em:

```text
dados/processados
```

Os dados originais permanecem preservados na pasta de dados brutos.

---

# 3. Execução com Docker

O projeto utiliza Docker Compose para executar os serviços necessários.

Primeiro, entre na pasta que contém o arquivo `docker-compose.yml`:

```powershell
cd caminho\para\desafio_dados\docker
```

Depois, inicialize os serviços:

```powershell
docker compose up -d
```

Para verificar os containers:

```powershell
docker compose ps
```

Com os serviços funcionando, execute a aplicação:

```powershell
docker compose run --rm app
```

O comando executará o pipeline Python dentro do container.
